## Why build yet another IRT package?

R already has excellent IRT packages such as mirt and TAM, so why write our own? The answer is a real engineering pain point: **once you have hundreds of thousands or millions of respondents, hundreds of items, and a multidimensional model, conventional implementations hit a memory wall.**

The E-step of IRT estimation (marginal maximum likelihood, MML) has to compute a posterior probability for "every respondent × every quadrature node". With a million respondents and the integration grid of a multidimensional model, that intermediate matrix easily runs to hundreds of gigabytes — the problem is not that it is slow, it is that it simply doesn't fit in memory. And large-scale literacy monitoring and national surveys operate at exactly that scale.

IRTC was designed for this: **a self-contained MML estimation engine with a C++ core (Rcpp/RcppArmadillo) and systematic performance engineering for large datasets.** It is published on CRAN under the GPL (≥ 2) licence, the source code is public on GitHub, and it comes with a comprehensive automated test suite and manuals in Chinese and English.

First, a word on where it fits, so you can decide whether to read on:

- **Routine analyses with thousands or tens of thousands of respondents**: mirt is an excellent choice — plenty of documentation, a mature ecosystem, no need to switch.
- **Hundreds of thousands of respondents or more, memory warnings, or multidimensional models on a million cases on an ordinary workstation**: IRTC was built for you.

## What it can do

**Models**: Rasch/1PL, 2PL, PCM, RSM, GPCM — the main models for dichotomous and polytomous items; unidimensional and between-item multidimensional structures; latent regression (background variables in the model), multiple-group analysis, case weights, and EAP estimates of individual ability. That list covers the vast majority of modelling needs in large-scale assessment.

**Performance design** (this is what sets it apart):

1. **Multithreaded E-step**: the work is naturally parallel across respondents, so more cores mean more speed.
2. **Streaming posterior computation**: respondents are processed in blocks and each block's posterior is used and discarded at once — **the full "respondents × nodes" matrix is never stored**. Memory use becomes proportional to block size instead of sample size, which is what lets a million cases run on an ordinary workstation.
3. **Dimension decomposition**: with between-item multidimensional structures, high-dimensional integrals are broken down into lower-dimensional ones, so the number of nodes doesn't explode exponentially with the number of dimensions.
4. **Analytic gradients + a hybrid Newton M-step**: fewer, more stable iterations.
5. **Automatic engine routing**: in `auto` mode the package chooses between the grid path (conventional) and the streaming path (large scale) according to the size of the data, and records why.

**Safeguards**: optional pruning of quadrature nodes speeds things up, and when it is used, the approximation error is checked empirically, layer by layer, and reported. By default the exact path is used — **acceleration never silently changes the statistical target.** That is a rule we set ourselves.

## Up and running in ten minutes

```r
# Install from CRAN
install.packages("IRTC")
library(IRTC)

# Example data shipped with the package: a respondent × item 0/1 response matrix
data(data.sim.rasch)

# Fit the model; you can also pass a data file path (CSV, Excel, SPSS)
mod <- irtc(data.sim.rasch, model = "1PL")

plain_summary(mod)          # Plain-language summary of the results
irtc_param_table(mod)       # Item parameter table
irtc_person_table(mod)      # Ability estimates with standard errors
```

For statisticians, the full interface is available — for example, a polytomous model with sampling weights, latent regression, and multithreading:

```r
mod <- irtc.mml.2pl(resp,
                    irtmodel = "GPCM",
                    pweights = w,                  # Sampling weights
                    formulaY = ~ region + gender,  # Background variables (latent regression)
                    dataY    = background,
                    method   = "auto",             # Chooses grid or streaming by data size
                    control  = list(n_threads = 2))
summary(mod)
irtc_itemfit(mod)
```

(Functions and arguments follow the package documentation on CRAN, which also includes the full manual and copy-paste example scripts. IRTC requires R ≥ 3.5.0.)

## A tip for practice: start small, then scale up

Whatever package you use, the right way to approach large-scale modelling is to **draw a subsample of 10,000–50,000 respondents first, sort out the model specification, item diagnostics, and convergence problems on it, and only run the full dataset once the approach is settled.** A full run can take several hours; on a subsample you iterate in minutes, and the project timeline can differ by an order of magnitude. At conventional scales IRTC's results agree with established implementations (this is part of its automated tests), so you are free to use whichever package you like for the subsample.
