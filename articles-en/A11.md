# A11 · Latent Regression: How Background Variables Should Enter an IRT Model

> Advanced IRT track. A key part of large-scale assessment methodology, and prerequisite knowledge for plausible values.

## The problem: what's wrong with estimating scores first and regressing afterwards?

Almost every assessment project eventually has to answer questions like: how is ability related to family background, region, or teaching variables? The intuitive approach takes two steps: first estimate each person's ability θ̂ with IRT, then use θ̂ as the dependent variable in a regression.

This "two-step method" has a systematic flaw: **θ̂ is a point estimate with measurement error, and different estimation methods have errors with different properties, so entering it directly into a regression produces biases in predictable directions.**

- Using **EAP or MLE point estimates** as the dependent variable: measurement error **attenuates** the regression coefficients (the effects of background variables are underestimated), and the shrinkage of EAP additionally distorts variances and subgroup differences — the fewer the items, the stronger the shrinkage and the more subgroup differences are underestimated.
- More insidiously, EAP shrinks **towards the prior mean**. If ability is estimated without background information, everyone shrinks towards the population mean, and part of a disadvantaged group's real disadvantage is "shrunk" away — your conclusions about equity are contaminated by the method itself.

In large-scale assessments with matrix sampling (each person takes only some of the items), individual measurement error is large and the bias of the two-step method cannot be ignored. That is why latent regression exists.

## The solution: move the regression inside the model

The idea of latent regression: **don't estimate individual scores first; make the ability distribution itself conditional on the background variables.** The model:

$$\theta_n \sim N(\beta_0 + \beta_1 x_{n1} + \dots + \beta_p x_{np},\ \sigma^2)$$

The response data and the background variables enter the likelihood **together**, and the item parameters, regression coefficients β, and residual variance are estimated in one step. As a result:

1. The estimates of β correctly carry the measurement uncertainty and are not attenuated.
2. Each person's ability posterior is conditioned on "responses + background", making the fullest use of the information.
3. Subgroup comparisons (sex differences, urban–rural differences) come straight out of the model, without shrinkage bias.

This is exactly the procedure of large-scale assessments such as PISA and NAEP: an IRT measurement model + latent regression (with all background variables entered after compression into principal components) → **plausible values (PVs)** drawn from each person's posterior for secondary analysts. PVs are essentially "multiple-imputation output from the latent regression model" — which also explains why the rules for using PVs are exactly those of multiple imputation (analyse each PV separately, then combine with Rubin's rules).

## In practice: how to do it in R

The TAM package is the standard tool in the large-scale assessment tradition:

```r
library(TAM)
# Y: matrix of background variables (regressed on ability)
mod <- TAM::tam.mml(resp = dat, Y = Y_background,
                    irtmodel = "PCM", pweights = w)
mod$beta        # latent regression coefficients
pv <- TAM::tam.pv(mod, nplausible = 10)  # draw plausible values
```

Our IRTC engine also has built-in latent regression and case weights (optimised for large samples); see the package documentation on CRAN for the interface.

**Key points for use:**

1. **The background model must be "broad"**: every variable that secondary analyses might use should enter the latent regression (or its principal components). If a variable is not in the background model, PV-based analyses of its relationship with ability are biased towards zero. This is the "hidden contract" of PV data: **only relationships covered by the background model are fully preserved.** Large-scale assessments compress hundreds of background variables into principal components and include them all precisely to make that contract as broad as possible.
2. **Weights go in at the same time**: sampling weights must be used in estimating the latent regression, not added afterwards.
3. **The intuition behind the conditioning paradox**: two students with the same total score but different backgrounds get different PV distributions, which beginners often find "unfair". The point is that PVs are designed for **population-level statistical inference** (recovering the joint distribution in the population), not for individual reporting. **PVs must never be used to give individuals a score** — that is the boundary of their use.

## When you need this heavy machinery

| Situation | Recommendation |
| --- | --- |
| Everyone takes the full test, 40+ items, only individual scores matter | The two-step method is acceptable (small error) |
| Studying "background × ability" relationships, moderate number of items | Latent regression, or one-step SEM modelling |
| Matrix sampling / large-scale monitoring | Latent regression + PVs: the industry standard, with no substitute |
| Using public data such as PISA | Follow the PV rules (analyse each PV + combine with Rubin's rules + the accompanying replicate weights) |

Latent regression is a classic example of merging a measurement model with structural analysis. Once you understand it, you will treat "scores" with an extra degree of caution: **every point estimate compresses information, and the way it compresses carries a statistical stance of its own.**
