# 34 · Geht IRT ohne Programmieren? – Grafische Oberflächen für IRT

> Der letzte Artikel hat R gelobt, aber manche wollen wirklich keinen Code anfassen. Dieser Artikel beantwortet ehrlich: Geht IRT ohne Programmieren? Ja, aber mit Preis. Wir klären Optionen und Abwägungen.

## Die direkte Antwort: Ja, aber kennen Sie den Preis

**IRT geht auch ohne Programmieren – es gibt Software mit grafischer Oberfläche (Bedienung per Mausklick).** Der „Klickweg“ hat aber seine Bequemlichkeiten und seine Grenzen. Ob er sich lohnt, hängt von Ihren Zielen ab.

Zuerst die Optionen auf diesem Weg.

## Option 1: spezialisierte IRT-Software mit grafischer Oberfläche

Es gibt kommerzielle Programme speziell für IRT- bzw. Rasch-Analysen, die Menüs und Schaltflächen statt Code verwenden. Sie haben ihren Platz in der Fachwelt, besonders in manchen traditionellen Messteams.

- **Vorteile**: Ein paar Klicks liefern Ergebnisse, die Lernkurve ist sanft, die Berichte oft übersichtlich.
- **Nachteile**: Meist ist eine Lizenz zu kaufen; der Funktionsumfang ist auf das beschränkt, was der Hersteller anbietet, was die Software nicht kann, geht nicht; auf einem Rechner ohne die Software kommen Sie nicht weiter; und der Analyseweg ist schlecht nachvollziehbar, die Reproduzierbarkeit schwach.

## Option 2: grafische Oberflächen für R

Im R-Ökosystem gibt es auch „grafische Hüllen“ (etwa jamovi oder andere Werkzeuge mit Oberfläche), die im Hintergrund weiter auf R beruhen, Ihnen aber eine Klickoberfläche bieten.

- **Vorteile**: kostenlos oder günstig; verbinden „kein Programmieren“ mit „R-Werkzeugen nutzen“.
- **Nachteile**: Die Oberfläche deckt meist nur einen kleinen Teil der Funktionen der zugrunde liegenden R-Pakete ab; für etwas komplexere oder maßgeschneiderte Analysen muss man doch wieder Code schreiben.

## Option 3: andere (oder eine KI) den Code schreiben lassen

Streng genommen keine „grafische Oberfläche“, aber ein praktischer Weg für alle, die nicht programmieren lernen wollen:

- Sie sind dafür zuständig, **zu klären, was Sie wollen, und die Ergebnisse zu verstehen**; das Codeschreiben übernehmen Menschen, die es können, ein KI-Assistent oder fertige Skriptvorlagen Ihres Teams.
- **Vorteile**: Sie nutzen alle Fähigkeiten und die Reproduzierbarkeit von R, ohne die Syntax lernen zu müssen.
- **Nachteile**: Sie müssen die Ergebnisse verstehen und beurteilen können, ob sie stimmen – **„keinen Code schreiben“ heißt nicht „die Prinzipien nicht verstehen“.** Wer die Prinzipien nicht versteht, kann auch gut geschriebenen fremden Code nicht richtig nutzen (genau dabei will diese Reihe helfen).

## Die entscheidende Abwägung: Bequemlichkeit gegen Obergrenze

Die Wahl in einem Satz:

> **Grafische Oberflächen kaufen Ihnen die Bequemlichkeit „schnell starten, keine Syntax lernen“; Code (R) kauft Ihnen die Freiheit „unbegrenzte Funktionen, Reproduzierbarkeit, Anpassbarkeit“.**

- Machen Sie nur **gelegentlich Standardanalysen in kleinem Rahmen ohne Anspruch auf neueste Methoden**, reicht eine grafische Oberfläche völlig; Sie müssen sich nicht aus Prestige zum Programmieren zwingen.
- Wollen Sie **neueste Methoden anwenden, große Datenmengen verarbeiten, strenge Reproduzierbarkeit und den Ablauf zu wiederverwendbaren Werkzeugen machen** (siehe Artikel 36), stößt die Oberfläche bald an ihre Grenze, und Sie kommen ums Programmieren nicht herum.

Für ein professionelles Team, das von IRT lebt, ist **Programmieren (besonders R) praktisch Pflicht** – denn Reproduzierbarkeit, Anpassung und lieferbare Werkzeuge sind das Fundament professioneller Dienstleistung (das Modell „Daten bleiben im Haus, Werkzeuge werden geliefert“ aus Artikel 7 beruht auf codebasierten Analysen, die in der Umgebung der Auftraggeber laufen).

## Ein Wachstumsweg als Kompromiss (für die meisten empfohlen)

Sie müssen nicht zwischen „nur klicken“ und „nur programmieren“ wählen. In der Praxis ist ein **schrittweiser** Weg oft am angenehmsten:

1. **Mit einer grafischen Oberfläche und dieser Reihe beginnen**, um Begriffe, Kurven und die Deutung der Ergebnisse zu verstehen – der wichtigste Teil, und er hat nichts damit zu tun, ob Sie Code schreiben können.
2. **Wenn der Bedarf komplexer wird, fertige Codevorlagen ausprobieren** (nur Datennamen und Parameter ändern) – ein Schritt Richtung Programmieren.
3. **Mit wachsender Sicherheit wollen Sie von selbst etwas R lernen**, weil Sie dann schon wissen, was es für Sie tun soll.

**Erst die Prinzipien verstehen, dann über Werkzeuge reden.** Wer die Prinzipien versteht und nur klicken kann, ist weit besser dran als jemand, der Code schreiben kann, aber nicht versteht, was er berechnet.

## Ein Satz zum Schluss

> **IRT geht auch ohne Programmieren – mit grafischer Spezialsoftware, Oberflächen für R oder indem andere bzw. eine KI den Code schreiben. Grafische Oberflächen kaufen „Bequemlichkeit“, zum Preis begrenzter Funktionen und schwacher Reproduzierbarkeit; Code (R) kauft „Freiheit“. Für die meisten bietet sich ein schrittweiser Weg an: erst mit Oberfläche und dieser Reihe die Prinzipien verstehen, dann nach Bedarf zum Code. Die Prinzipien zu verstehen ist immer wichtiger, als Code tippen zu können.**
